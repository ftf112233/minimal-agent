# AI Prompt 与问题解决记录

开发辅助工具：WorkBuddy（Kimi）。
以下按实际开发顺序记录我给出的关键 prompt、遇到的问题与解决思路。
原则：架构和取舍由我定，AI 负责起草、补边界情况和查漏补缺。

## 1. 需求拆解

> **Prompt**："这是笔试题文档链接。先不要写代码，逐条梳理题目要求：基本循环分几步、
> 工具机制要求什么、session 和 context 各自的考察点、提交物清单。文档没指定的部分单独列出来。"

先让 AI 拆题而不是直接写代码。拆完发现几个文档没指定、必须自己定的点：

| 未定项 | 我的决策 | 理由 |
|--------|---------|------|
| 语言 | Python | Runtime 自研最直观，依赖最少，逐行讲解成本低 |
| LLM | DeepSeek | 国内直连、OpenAI 兼容协议、价格低 |
| 输出协议 | ReAct 文本解析 | 见第 2 节，这是最关键的一个决策 |

## 2. 关键决策：ReAct 文本协议 vs 原生 function calling

> **Prompt**："DeepSeek 支持原生 tool calling，但题目要求'实现 LLM 输出的解析逻辑，
> 提取思考过程、工具调用或最终答案'。用原生 function calling 算不算跑题？"

AI 的分析和我一致：**用原生 function calling 等于把考题跳过了**——解析逻辑是题目
明确要考察的东西。所以定了 ReAct 文本协议（Thought / Action / Action Input /
Final Answer），自己写解析器。代价是对模型格式遵从度有要求，后面用
"纠正提示 + 原文兜底"来缓解（见第 4 节）。

## 3. 问题：Observation 用什么 role 发给模型？

> **Prompt**："ReAct 文本模式下工具结果要回灌给模型。OpenAI 协议的 role=tool
> 必须搭配 tool_call_id，文本模式没有这个字段，怎么办？"

讨论了三个方案：
1. `role=tool` —— 协议层直接报错，排除；
2. `role=system` —— 语义被污染，system 消息应该是稳定指令，排除；
3. `role=user` + `Observation: ` 前缀 —— 业界最小实现的通行做法，采用。

附带解决了一个问题：统计"用户轮次"时不能把 Observation 算进去，
所以消息加了内部 `kind` 字段（input / observation / assistant）区分。

## 4. 问题：模型不按规定格式输出怎么办？

> **Prompt**："如果模型第一步就输出一段散文，既没 Action 也没 Final Answer，
> loop 应该怎么处理？直接报错、重试、还是兜底？"

最终方案是三层：解析器宽容提取（容忍代码块、全角冒号、JSON 尾随杂质）→
注入格式纠正提示让模型重来（**一轮最多一次**，防"纠正-再错-再纠正"死循环）→
仍不合规则原文兜底返回。取舍依据：宁可给用户不完美的答案，不让用户干等。

## 5. 问题：calculator 的安全问题

> **Prompt**："calculator 如果直接用 eval，用户输入 `__import__('os').system(...)`
> 就是任意代码执行。怎么从根上防？"

改用 `ast.parse(mode="eval")` + 白名单节点递归求值：只允许数字字面量、
六种二元运算符、正负号，其余节点类型（Name / Call 等）一律拒绝。
这是结构上的免疫，而不是黑名单封堵。测试里专门覆盖了注入向量。

## 6. 问题：context 压缩的语义

> **Prompt**："压缩时新摘要直接覆盖旧摘要行不行？最近几条原文要不要留？"

两个结论：
- **合并而非覆盖**——否则早期信息（比如用户第一轮说的城市）永久丢失；
- **最近窗口留原文**——保证"我刚才说的那个"这类追问的指代不失真。
- 另外补了降级：LLM 摘要失败时退化为尾部截断，压缩失败不能让对话崩。

摘要的放置方式也讨论过：放 system prompt 尾部（稳定、约束力强、
不被滑动窗口截掉），而不是混进 user 消息流。

## 7. 问题：测试环境的依赖

> **Prompt**："本机环境装不上 pytest。测试框架怎么选？"

干脆改用标准库 `unittest` 重写。意外的好处：**测试零依赖**，
reviewer clone 下来 `python -m unittest discover -s tests -v` 直接能跑，
不用装任何东西。

## 8. 验证与收尾

> **Prompt**："现在跑全部测试，然后用 mock 模式做一次端到端冒烟：计算、天气、
> 切窗口记待办、看 trace。"

42 个用例全绿；mock 冒烟确认了多 session 切换和 trace 记录正常。
最后用脚本化 MockLLM 精确编排 loop 走向，把容错分支（格式纠正、最大步数、
LLM 全挂、会话隔离）都补了测试。
